# Запуск через Docker

Требуется установленный Docker Desktop.

```
cd PROD
docker compose up --build
```

- Backend (FastAPI): http://localhost:8000 (документация API: http://localhost:8000/docs)
- Frontend (Vite): http://localhost:5173

## Вход в систему

При первом запуске (если таблица пользователей пуста) создаётся учётка:

- Логин: `admin`
- Пароль: `admin123`

Рекомендуется сменить пароль после первого входа (раздел пользователей / `PUT /api/users/{id}`). Сейчас в системе только проверка входа — все авторизованные пользователи имеют одинаковый доступ, разграничение по ролям пока не включено.

Для продакшена обязательно задайте свой `JWT_SECRET` в `docker-compose.yml` (сейчас используется дефолтный dev-секрет в `backend/app/auth.py`).

## Реестр поездок

Раздел «Реестр поездок» во фронтенде позволяет загрузить `.xlsx`-выгрузку (сейчас поддержан формат OZON). При импорте сначала открывается окно выбора **«Источник»** (OZON / WB / ATI / Прямые / Прочие — у каждого свой цвет тега) и **«Перевозчик»** (пока единственный плейсхолдер «Перевозчик 1» — заменится на реальный реестр перевозчиков, когда он будет поднят), и только потом — выбор файла. Оба значения сохраняются в каждой созданной/обновлённой строке и выводятся первыми двумя колонками таблицы.

Импорт создаёт **одну запись на каждую строку файла** — без группировки по неделям/водителям, включая отменённые заявки («Статус заявки» = «Отменено»). Если водитель или машина не найдены в базе — создаются автоматически. Повторный импорт того же или обновлённого файла не создаёт дублей: строки обновляются по «№ заявки» (источник/перевозчик при этом перезаписываются на выбранные в текущем импорте).

Над таблицей: фильтр по датам отгрузки «с»/«по» (по умолчанию — последние 30 дней), мультивыбор по статусу/водителю/машине, и сводка «поездок в выборке» + «сумма по выборке», пересчитываемая по всем активным фильтрам. Таблица сортируется по любому столбцу (клик по заголовку), по умолчанию — по дате отгрузки от новых к старым. Количество строк на странице настраивается (50/100/300/500).

Старая логика еженедельной агрегации (`TripBatch`) сохранена в коде (`backend/app/importers/trip_registry.py`, функция `import_trip_registry`) для будущего дашборда, но больше не используется при импорте.

## Топливо

Раздел «Топливо» поддерживает импорт `.xlsx`-выгрузок с топливных карт (сейчас проверен формат E100: колонки `ID | Дата | АЗС | Карта № | Марка ТС | Гос. Номер ТС | Объем | Сумма | ID транзакции`) и ручной ввод записей.

Импорт не требует выбора источника/перевозчика (в отличие от поездок) — достаточно выбрать файл. Строки upsert'ятся по собственному `ID` транзакции из файла, поэтому повторный импорт того же или частично пересекающегося файла не создаёт дублей. Машина определяется по госномеру той же логикой нормализации/сопоставления, что и в реестре поездок (общий код вынесен в `backend/app/importers/common.py`); если машина не найдена — создаётся автоматически.

Кнопка «Добавить запись» открывает форму ручного ввода (дата, машина из справочника, АЗС необязательно, объём, сумма) — такие записи сохраняются в той же таблице, что и импортированные, и помечаются тегом «Вручную» (определяется по отсутствию `external_id`, отдельного флага нет).

Над таблицей — те же фильтры, что и в поездках: диапазон дат (по умолчанию 30 дней), мультивыбор по машине/АЗС, сводка по выборке (количество, объём в литрах, сумма), сортировка по клику на заголовок, постраничный вывод.

## Данные

SQLite-база лежит в `PROD/data/db/transport_crm.db` — создаётся автоматически при первом запуске, переживает `docker compose down`/пересборку образов.

## Режим

Сейчас собран dev-режим: папки `backend/` и `frontend/` подключены как volume, поэтому изменения в коде подхватываются на лету (uvicorn --reload, vite dev server) без пересборки контейнера. Для пересборки после изменения зависимостей (requirements.txt / package.json):

```
docker compose up --build
```

## Важно про Dropbox

Эта папка (`Transport CRM`) синхронизируется через Dropbox. `PROD/data/db` (файл базы) и `PROD/frontend/node_modules` после `npm install` внутри контейнера будут активно меняться/расти — это может создавать лишнюю нагрузку на синхронизацию или конфликты версий файлов. Если будут проблемы — можно добавить `PROD/data` и `PROD/frontend/node_modules` в исключения синхронизации Dropbox (Selective Sync / Ignore).
